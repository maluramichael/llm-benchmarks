# 2026-10-30: PC RTX 3090 24 GB

One run of the standard benchmark. Results table and prompt are in the [README](../README.md). It adds three extra models outside classes S to XL and F: Qwen3.8-Flash-Next as a huge model that does not fit into 24 GB and loads experts from RAM with Strata, LFM3 1.7B by Liquid AI as a particularly small model, and Qwen3-Coder-30B-A3B as a coding model. There are also two new tests for all models on the card: logic and coding questions, and concurrent requests. Prompts and settings are the same as in the [run from 2026-10-26](2026-10-26-pc-rtx-3090-24gb.md).

## Tests

### Strata 0.2.8 (engine 0.1.54), Qwen3.8-Flash-Next IQ3_S (Extra)

- **Engine + version:** Strata 0.2.8 ([github.com/Niko1221/Strata](https://github.com/Niko1221/Strata)), engine 0.1.54 for Windows with CUDA 13, OpenAI-compatible API
- **Model (exact tag):** Qwen3.8-Flash-Next-GSQ-RCO-IQ3_S (ISTA-DASLab, 2 GGUF parts with 77.9 GB, installed through the Strata app, 86.9 GB including the vision part)
- **Quantization:** IQ3_S (GSQ-RCO)
- **Class:** Extra (Mixture of Experts, does not fit into VRAM, Strata streams experts from RAM)
- **Max context:** 32,768 (at 65,536 Strata silently cut the input to 48,844 tokens, so the test failed)
- **Cold load (s):** 91.31
- **TTFT cold (s):** 92.36
- **TTFT warm (s):** 3.44
- **TTFT with cache (s):** 3.54 (no prompt cache, 0 tokens from the cache)
- **Prompt processing tok/s:** 2,427
- **Generation tok/s:** 85.0
- **Generation tok/s at max context:** 89.0 (prompt processing 2,567)
- **Notes:** Strata only offers chat requests, no raw text completion. The prompts were therefore sent as one message with thinking turned off, the chat template adds about 12 tokens. Instance with 131,072 context, KV cache INT8, profile Performance, vision on, MTP speculation automatic (about 49 percent of proposed tokens accepted). Uses 22.3 GB VRAM, Strata keeps the rest in RAM. Answers often ended before 256 tokens, so generation is measured over fewer tokens. The PC was not freshly restarted (about 9.5 hours uptime), the Strata window stayed open. An extra request with 128k outside the protocol ended in blue screen 0x116 (nvlddmkm). Measured with a custom script based on the standard benchmark script.

Each answer ends with a line "ANTWORT: ..." that is checked automatically; written code runs against fixed tests. Each question is a separate chat request, temperature 0, seed 42, context 16,384, at most 8,192 tokens with thinking and 1,024 without. All runs use llama.cpp build 12001, LFM3 also Ollama 0.40.13. Qwen3.8 27B with thinking solves all 65 questions and thinks briefly (about 300 tokens per question). Flint reaches 60 with thinking and, at 57 without thinking, is almost as good as Qwen3.8 27B; all 4 errors with thinking and 7 of the 8 errors without thinking occur because Flint thinks up to the token limit and writes no answer line. Qwen3 14B gains 8 points from thinking and makes no coding errors. Qwen3.5 4B gets worse with thinking (40 instead of 44): 24 questions run into the 8,192 tokens without an answer. LFM3 1.7B reaches 56 to 59 points with thinking, but needs four to six times as many tokens as Qwen3.8 27B; without thinking it often writes the answer line as "ANWTORT:" (26 and 32 format errors, with tolerance 39 and 38 points). Qwen3-Coder solves all arithmetic and coding tasks but fails on family riddles and trick questions. Since Qwen3.8 27B gets the full score, the question set only separates smaller models.

## Concurrent requests

For a shared worker with several users or jobs at the same time. One llama-server (build 12001) with 8 slots and 16,384 context shared across all slots, otherwise like the standard run (`-ngl 99 -fa on`). Each request gets its own text section with the summary task (1,024 tokens) and generates exactly 256 tokens (ignore_eos), without prompt cache. Levels with 1, 2, 4 and 8 concurrent requests, 3 rounds each, median. Values per cell: total generation tok/s / generation per request tok/s / seconds to first token (median).

With 8 concurrent requests the card delivers 2.4 to 2.9 times the tokens on the dense models, but each individual request becomes two to three times slower. Qwen3.8 27B finishes 8 summaries at once in 21 s instead of about 54 s one after the other, but with 8 chat users everyone waits up to 6 s for the first word. The two MoE models behave differently: Qwen3-Coder scales almost like Qwen3.5 4B, Flint only by a factor of 1.9 and with long waits for the first token, since processing several prompts is expensive on Flint. With 8 slots Flint uses almost all of the VRAM.

## Summary

LFM3 1.7B is the fastest model on this card: about 19,000 to 21,000 tok/s prompt processing and about 300 tok/s generation, a good twice as fast as Qwen3.5 4B (class S), plus 128k context with only about 6 GB VRAM. Ollama processes prompts slightly faster, llama.cpp generates slightly faster. Qwen3.8-Flash-Next runs with Strata at 85 tok/s and 2,427 tok/s prompt processing despite its 87 GB model size, which is faster than Qwen3.8 27B with llama.cpp (42.2 tok/s), but it takes 91 seconds to load, has no prompt cache and cuts inputs above about 48,000 tokens. Aborts: a GPU driver reset on LFM3 with 256k context, and a blue screen on Strata from a 128k request outside the protocol. Qwen3-Coder-30B-A3B generates at 162 tok/s, as fast as Qwen3.5 4B. In the logic and coding test, Qwen3.8 27B with thinking gets 65 of 65 questions, Flint 60, Qwen3 14B and LFM3 59, and Qwen3.5 4B often gets stuck thinking. With 8 concurrent requests, total throughput rises to 1.9 to 2.9 times, but each request becomes clearly slower.
